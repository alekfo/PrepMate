## Безопасность — следующие этапы

- [ ] **Cloudflare Turnstile на регистрации** — с 01.07.2026 участились скриптовые регистрации ботами: случайные логины (10 случайных строчных букв) + чужие реальные email (в т.ч. корпоративные, не одноразовые — текущий `_DISPOSABLE_EMAIL_DOMAINS` их не ловит). Часть аккаунтов "подтверждает" email за 19–90 сек после регистрации — слишком быстро для человека; похоже на автопрогрев ссылок корпоративными email-шлюзами безопасности (Safe Links/Proofpoint и т.п.), а не реальное действие пользователя. Реальных интервью с этих аккаунтов почти нет — похоже, форма используется для валидации чужой email-базы (email harvesting), а не для получения бесплатного доступа к сервису. Honeypot и блок одноразовых доменов не помогают, т.к. запросы, судя по всему, идут напрямую POST без рендера страницы/JS.
  План: подключить Cloudflare Turnstile (бесплатно, без переноса домена под Cloudflare proxy — просто JS-виджет на `register.html` + серверная проверка токена через `siteverify` в `register` view). Ключи `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` через `.env`.
  Отложено — сначала понаблюдать за поведением ботов, используя уже добавленное логирование IP.

## Технический долг

- [ ] **N+1 в `flashcards` view** — `vp.sessions.filter(status='completed').exists()` вызывается в Python-цикле, один SQL на каждую вакансию. Переписать через аннотацию `Count` + фильтр в ORM.
- [ ] **`index` view грузит все сессии без лимита** — `InterviewSession.objects.filter(user=request.user)` без среза. Добавить `[:50]` или переписать дедупликацию через SQL `DISTINCT ON`.
- [ ] **`if True:` в `statistics_overview`** — мёртвый блок, убрать лишний уровень отступа.
- [ ] **`interviews_used` race condition** — обновляется через `update()` без `F()` в `start` view, потенциальный race при одновременных запросах одного пользователя. Заменить на `F('interviews_used') + 1`.
- [ ] **Старые `Feedback` без тегов** — поля `weakness_tags` / `strength_tags` пустые для сессий до введения тегов. Блок «Динамика навыков» для них будет пустым. Решение: мириться или сделать ретроспективную оценку.
- [ ] **`SessionAdvice` генерируется синхронно** — при большом числе сессий без советов страница статистики будет долго грузиться. Решение: фоновая задача (Celery) или пагинация генерации.
- [ ] **Нет health check в docker-compose** — при падении `web` контейнера nginx будет отдавать 502 до рестарта. Добавить `healthcheck` в docker-compose.yml.
