## Производительность и масштабируемость

### Текущее состояние
Каждый вызов Claude API (~3–8 сек) — синхронный блокирующий I/O. Django-воркер занят на всё время ожидания ответа.

- `runserver` (dev) — однопоточный, параллельных запросов нет.
- Gunicorn (prod) — N воркеров = N параллельных Claude-вызовов. Проблемы начинаются при ~20–50 одновременных активных сессиях.

### Задачи

- [ ] **Async views + httpx** — перевести `generate_questions` и `evaluate_answer` на `async def` + `httpx.AsyncClient`. Разблокирует воркер во время ожидания API.
- [ ] **Celery + Redis** — вынести Claude-вызовы в фоновые задачи. Пользователь получает страницу сразу, результат подгружается (polling или WebSocket).
- [ ] **Rate limit handling** — добавить retry с экспоненциальной задержкой при `429` от Anthropic API (`tenacity` или вручную).
- [ ] **Мониторинг времени ответа** — логировать время каждого Claude-вызова, чтобы отслеживать деградацию.
